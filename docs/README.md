# OctoAcme Project Management Docs

This directory is the central landing page for OctoAcme’s project management guidance. It brings together the core process documents used to initiate, plan, deliver, release, and improve work across projects.

## Overview

OctoAcme uses a lightweight, cross-functional project management model built around a clear lifecycle:

- Initiate and align stakeholders
- Plan scope, milestones, and risks
- Execute in iterative delivery rhythms with clear ownership
- Track progress, escalate blockers, and communicate status
- Release with checks and rollback readiness
- Review outcomes and improve continuously

The goal is to keep delivery predictable, transparent, and measurable while ensuring teams work with shared context and a consistent set of operating practices.

## Project management process summary

### 1. Initiation
Define the problem, validate business need, and align stakeholders before work begins. The project team creates a one-pager, outlines success metrics, and confirms a decision gate before moving into planning.

### 2. Planning
Turn the approved initiative into an actionable roadmap and backlog. This includes kickoff, prioritization, estimates, milestones, QA planning, and documentation of risks and dependencies.

### 3. Execution and tracking
Deliver in regular delivery rhythms with clear ownership, daily standups, and weekly progress reviews. The team tracks progress against milestones, resolves blockers quickly, and communicates status with stakeholders.

### 4. Release and deployment
Complete release readiness checks, run smoke tests, deploy with rollback plans, and communicate changes to stakeholders and support teams.

### 5. Retrospective and improvement
Capture what went well, what needs improvement, and what actions must be completed to improve delivery quality and team effectiveness over time.

## Operating principles

- Customer-first problem solving
- Iterative delivery of small, testable increments
- Clear ownership and accountability
- Data-informed decision making
- Psychological safety and continuous learning

## How to use these docs

- Start with the overview and initiation guide for new work.
- Use the planning and execution docs during project delivery.
- Refer to risk, release, and retrospective guidance as the project evolves.
- Keep project artifacts updated in the repo so the team has one source of truth.
